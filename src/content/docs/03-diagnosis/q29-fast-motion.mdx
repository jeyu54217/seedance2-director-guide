## 一句話

動作一快，兩種症狀：物體消失變形（人物跑太快），背景漂移模糊（攝影機動太快）。根因同一個——Temporal Attention 的 token 匹配在大位移時失效。

## 為什麼一快就壞？

[Q4：注意力機制](../01-basics/q04-attention/) 的 Temporal Attention 負責跨幀比對 token：第 1 幀「奔跑中的左手」要和第 2 幀「同一隻左手」對齊，第 1 幀的「背景牆壁」也要和第 5 幀的「同一面牆」對齊。比對的依據是 [Q6：時間步調節](../01-basics/q06-timestep/) 的位置編碼——兩個 token 的空間位置 + 時間位置，取餘弦相似度。

餘弦相似度的特性：**小位移靈敏，大位移驟降。** 物體在相鄰幀之間位移一大，相似度跌破匹配閾值，Temporal Attention 判定「這兩個 token 不是同一個東西」——token tracker 從這一幀開始跟丟。

物體動太快 → 物體的 token 跟丟 → 手消失、臉變形、邊緣模糊。攝影機動太快 → 背景的 token 跟丟 → 牆壁漂移、家具扭曲。

**同一個機制，差別只在「誰在動」。** 這不是 [Q24：肢體融化](q24-limb-melting/) 的 SNR 崩潰（去噪把肢體當雜訊砍），也不是 [Q27：物理失敗](q27-physics-failure/) 的 Physics Reward 表面模擬——這是 token 追蹤層面的失敗。消失的東西不是物理不合理，而是 attention 直接跟丟了。

## O(n²) 窗口截斷：連試圖匹配的機會都沒有

[Q13：15 秒限制](../02-seedance/q13-15sec-limit/) 揭露了根本的運算瓶頸：Self-Attention 佔 DiT 運算的 60–76%。實際部署時，Temporal Attention 的匹配窗口被截斷為有限幀數。

高速場景中，物體或背景在幾幀之內就移出截斷窗口——Temporal Attention 連嘗試匹配的機會都沒有。**窗口小 + 位移大 = 雙重打擊。**

[Q14：運鏡機制](../02-seedance/q14-camera-motion/) 的訓練視覺先驗從反面印證：訓練數據中 slow camera movement 遠多於 fast whip pan，慢速連續動作遠多於高速變速動作。模型根本沒看過足夠的高速樣本。

## 解法

| 場景 | 做法 |
|---|---|
| **物體高速運動** | 降速——慢走 > 奔跑。拆成多段短鏡頭。Prompt 指定 "slow, continuous movement, consistent speed" |
| **攝影機快速運鏡** | 慢速 dolly-in > 快速 zoom——dolly 幀間位移均勻，zoom 邊緣非線性位移更容易觸發匹配失敗 |
| **必須高速（兩者通用）** | CameraCtrl + FreeInit + Tile ControlNet 三連：CameraCtrl 給 explicit camera path，FreeInit 重設初期雜訊強化一致性，Tile ControlNet 鎖定局部空間結構 |

Euler sampler（[Q7：Flow Matching](../01-basics/q07-flow-matching/) 連續時間路徑比離散 DDPM 平滑），Steps ≥ 25 給 Temporal Attention 足夠的修正機會。

完整參數見 [Part 4：ComfyUI 節點速查](../04-workflow/comfyui-nodes/)，打鬥與大運鏡 preset 見 [Part 4：場景組合](../04-workflow/scene-presets/)。

:::tip[🎬 導演要點]

快速 = Temporal Attention 的極限測試。物體動太快、攝影機動太快——根因同一個，解法同一套。

**慢速、連續、均勻 > 快速、複雜、變速。** 一定要快：CameraCtrl + FreeInit + Tile ControlNet 三連 + Steps ≥ 25。

:::
