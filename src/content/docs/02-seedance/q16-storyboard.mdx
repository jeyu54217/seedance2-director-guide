## 一句話

Seedance 論文未揭露 storyboard 圖片的內部解析步驟。從公開架構推論：多格 storyboard 提供的是**多時間點的視覺錨點**，模型在 denoising 過程中同時看到所有 panel 的視覺條件，Temporal Attention 在時間軸上補出 panel 之間的過渡——包括運鏡。

## 單張參考圖能做到的極限

單張 mood board 只有一個視覺條件。模型生成每一幀時，看到的都是同一組顏色、光影、構圖訊號。你可以用它鎖定角色外觀和風格，但無法用它控制「第 3 秒要切到 close-up」。

多格 storyboard 每一格對應不同的時間點。Panel 1 是 wide shot，panel 2 是 close-up，panel 3 是低角度——模型拿到的不是一個條件，而是多個時間點的多個條件。這是 storyboard 比單張圖更有控制力的根本原因。

## Seedance 論文實際寫了什麼

**Seedance 1.0**（[arxiv:2506.09113](https://arxiv.org/abs/2506.09113)）描述的是架構層面的 multi-shot 能力。核心設計是 Multishot MM-RoPE——一種位置編碼，讓多個 shot 的 visual token 和 text token 在同一個序列中交錯排列，每個 shot 有自己的 caption。Denoising 時，模型同時看到所有 shot 的資訊，不是逐 shot 分開生成。跨 shot 角色一致性的來源就是這個——不同 shot 的 visual token 在 attention 層有直接交換，不需要靠 prompt 來維持。

**Seedance 2.0**（[arxiv:2604.14148](https://arxiv.org/abs/2604.14148)）產品頁面寫 "It can even directly reference text-based storyboards"，官方 prompt 範例列出提取項目：shot scale、camera movement、visuals、copy（storyboard 上的文字標註）。但論文中沒有任何內部解析步驟的描述——這是一篇 system/evaluation paper，不是 architecture paper。

## 為什麼給 storyboard 會自動產生運鏡

不需要發明 Shot Decomposition 模組來解釋。從已知架構可以推論：

Seedance 1.0 的 multi-shot 序列中，每個 shot 的 visual token 帶著自己的 3D RoPE 時間位置編碼。當你餵 storyboard 的 panel 1（wide shot）和 panel 2（close-up），它們被當成不同時間點的 visual condition。Temporal Attention（[Q4：時空注意力的分工](../q04-spatial-temporal/)）在生成過渡幀時，看到的 condition 從「wide shot 構圖」漸變到「close-up 構圖」。模型訓練資料中 wide→close-up 的典型過渡就是 push-in——所以它自動生成 push-in。

運鏡來源是**預訓練視覺先驗**（[Q14](../q14-camera-motion/)），storyboard 的角色是給這個先驗提供明確的起點和終點。

Panel 之間的過渡不是被「指定」的，是被「補出來」的。這就是為什麼沒有寫任何運鏡術語，輸出仍然會有鏡頭運動。

## 學術界怎麼做 storyboard-to-video

Seedance 沒寫的，學術界有公開做法。目前兩條路線：

| 路線 | 做法 | 代表論文 |
|---|---|---|
| LLM-based planning | 外部 LLM 先把文字拆成 shot plan（鏡位、運鏡、時長），影片模型照 plan 生成 | STAGE (CVPR 2026), CoAgent |
| Architecture-level multi-shot | 在 DiT 內部處理 shot 邊界，denoising 時學 shot 之間的關係 | ShotAdapter (CVPR 2025), Seedance 1.0 |

**LLM-based**——STAGE（[arxiv:2512.12372](https://arxiv.org/abs/2512.12372)）：Director Agent（LLM）把故事展開成結構化 shot plan，每個 shot 標明 description、camera angle、shot scale。STEP2 模型為每個 shot 生成 start frame 和 end frame，再用 I2V 模型填滿中間。

**Architecture-level**——ShotAdapter（[arxiv:2505.07652](https://arxiv.org/abs/2505.07652)）：在 pre-trained DiT 中加入 transition token（讓模型學會 shot 之間的 cut）和 local attention masking（限制 text token 只 attend 自己的 visual token，防止跨 shot prompt 汙染）。不需要外部 LLM。

Seedance 1.0 論文的描述更接近後者（原生 multi-shot、架構內建），但 2.0 的 "directorial reasoning" 說法暗示可能混合了 LLM-based planning。**目前沒有公開資訊確認 2.0 的具體實作。**

:::tip[🎬 導演要點]
- **Storyboard 的價值是提供多時間點的構圖錨點**——不是風格參考。角色外觀統一交給 @ 角色參考圖（[Q11](../q11-at-tags/)）
- Panel 之間的空間差異會影響輸出運鏡，但模型是推斷，不是執行指令。想精確控制，在 prompt 中明確寫運鏡術語（[Q14](../q14-camera-motion/)）
- 實戰技巧見 [Q17：Storyboard 實戰](../q17-storyboard-practice/)——面板數、文字滲入防範、與角色圖的分工
:::

:::caution[⚠️ 誠實揭露]
Seedance 1.0/2.0 論文均未描述 storyboard 圖片的內部解析機制（panel 分割、OCR 文字讀取、Shot Decomposition 步驟）。「為什麼給 storyboard 會自動產生運鏡」段落為基於 Seedance 1.0 公開架構（MM-RoPE multi-shot 序列 + Temporal Attention 幀間平滑）的推論，非官方確認的實作細節。學術界做法（STAGE、ShotAdapter、CoAgent）引用自公開論文，不等於 Seedance 內部實作。
:::
