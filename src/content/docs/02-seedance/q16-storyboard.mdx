## 一句話

Seedance 論文沒有描述 storyboard 的內部機制。從社群行為反推：storyboard 走的是標準 vision encoder（整張圖編碼，無 panel 分割、無獨立 OCR），model 透過預訓練先驗理解 grid 結構，文字標註被 encoder 的 emergent OCR 能力部分讀取——但文字同時被當成 visual texture，所以可能滲入輸出。

## 已知行為

要反推機制，手上有五個可重現的社群觀察：

1. **Storyboard 比單張 mood board 更能控制 shot 結構和運鏡**（nemovideo.com、oimi.ai 案例：12 格註釋 storyboard 一次生成成功）
2. **Panel 數 ≤4 格效果最好，越多越容易亂**（morphic.com："With too many references, the model struggles to judge which features take priority"）
3. **文字標註會滲入輸出畫面**（OpenArt Handbook：需手動加 "no text overlay on screen" 來防止）
4. **Prompt 必須描述 panel 之間的敘事邏輯，model 不會自動理解**（OpenArt Handbook："describe the narrative logic between panels in your prompt"）
5. **ComfyUI 直接餵整張 contact sheet，不切片**（`ByteDance2ReferenceNode`）

## 三種可能的機制

### A：整張圖當成單一 visual condition

Storyboard 和 mood board 走同一條路——vision encoder 把整張圖編碼成 visual tokens，注入 cross-attention。沒有 panel 分割、沒有文字提取。

Panel 之間的空間變化（左上 wide shot、右上 close-up）被保留在 feature map 中，model 靠預訓練先驗學到「空間結構變化的條件 → 時間上有 shot 變化」。運鏡由 Temporal Attention 和 [Q14：預訓練視覺先驗](../q14-camera-motion/) 補出。

| 觀察 | 吻合？ |
|------|--------|
| Panel 越多越差 | 是——每格空間越小，特徵越模糊 |
| 文字滲入 | 是——文字 = visual texture，沒被提取 |
| Prompt 描述敘事邏輯是必須的 | 部分——model 靠預訓練先驗推斷 shot 過渡，但沒有 prompt 引導會偏離意圖 |
| 文字能被讀取 | **否——沒有 OCR 能力** |

### B：Vision encoder + Prompt 引導 + emergent OCR

在 A 的基礎上多加兩層：(1) prompt 文字引導 cross-attention 在不同時間段關注 feature map 的不同空間區域；(2) vision encoder（SigLIP/CLIP 等級）在大量 image-text pair 訓練中獲得 emergent OCR——能識別圖片中的文字為語義資訊，但文字同時保留為 visual token，沒有被分離。

**關鍵證據**：OpenArt Handbook 說必須在 prompt 中描述 panel 之間的敘事邏輯。這表示 model 需要 prompt 來理解「panel 1 和 panel 2 之間是什麼關係」——vision encoder 提供空間結構，但**敘事理解來自 prompt，不是來自 VLM**。

oimi.ai 的 12 格案例中，storyboard 上的運鏡註釋（"camera follows wagon"、"camera glides into tavern"）確實影響了輸出——但如果 model 沒有讀取這些文字的能力，效果應該和沒有註釋的 storyboard 一樣。文字滲入 bug 反過來證明了同一件事：文字被讀取了（作為語義），也被保留了（作為 visual texture），兩者沒有分離。

| 觀察 | 吻合？ |
|------|--------|
| Panel 越多越差 | 是——空間 attention 稀釋 |
| 文字滲入 | 是——文字同時是語義和 texture，未被分離 |
| Prompt 描述敘事邏輯是必須的 | 是——vision encoder 提供結構，prompt 提供敘事 |
| 文字能被讀取 | 是——emergent OCR，非獨立 pipeline |

### C：前處理切片 + 獨立 panel 注入

系統（或使用者）先切片 → 每個 panel 作為獨立 reference image 編碼和注入，類似 @image1、@image2 的多圖機制。

**被兩個觀察直接否定**：(1) ComfyUI 餵整張 contact sheet 就能 work——如果切片是必要路徑，這不可能；(2) 文字滲入 bug——如果 panel 獨立編碼，文字只會是條件，不會出現在畫面中。

Seedance 支援最多 9 張 reference，容量上和九宮格對應——但這只能證明 C 是可行的**替代方案**（使用者自己切好上傳九張圖），不是內部預設行為。

## 證據指向

**做法 B 最符合所有觀察**，但需要一個修正：

我之前把 B 描述為「prompt 引導 spatial attention 在不同 timestep 關注不同區域」——這層細節（spatial attention 分配機制）是推論，沒有直接證據。社群證據實際上支持的是更保守的版本：**vision encoder 提供含空間結構的 visual feature，emergent OCR 讀取文字標註，prompt 提供敘事邏輯來串接 panel 之間的關係**。model 如何把這三者整合——是在 attention 層、還是 embedding 層、還是 denoising schedule 層——論文沒寫，社群也沒有揭露。

:::tip[🎬 導演要點]
- **≤4 panel（2×2）是甜蜜點**——格數越多每格越模糊，attention 越稀釋
- **文字標註是雙面刃**——會被讀取但可能滲入畫面。運鏡術語寫在 prompt 中比寫在 storyboard 上更安全
- **Prompt 必須描述敘事邏輯**——只寫 "Use reference image to generate video" 不夠，要說明 panel 之間的關係和節奏
- 實戰技巧見 [Q17：Storyboard 實戰](../q17-storyboard-practice/)
:::

:::caution[⚠️ 誠實揭露]
Seedance 1.0/2.0 論文均未描述 storyboard 內部機制。做法 A/B/C 為從社群行為反推的假設。做法 B 中 vision encoder 的 emergent OCR 基於 SigLIP/CLIP 的已知能力類推，prompt 引導機制基於 DiT cross-attention 標準行為推論——均未經 Seedance 論文或官方文件確認。
:::
