## 一句話

Seedance 把整張 storyboard 當成一張圖編碼，靠 prompt 理解 panel 之間的敘事關係；文字標註會被讀取，但同時留在視覺特徵中，可能滲入輸出畫面。

## 一張圖為什麼能產生多個鏡頭

單張 mood board 只有一組顏色、光影、構圖——model 在每一幀看到的是同一個條件。但 storyboard 的 grid 佈局本身就帶有空間變化：panel 1 是 wide shot，panel 2 是 close-up，panel 3 是低角度。Vision encoder 輸出的 feature map 保留了這個空間結構——不同 spatial position 帶著不同 panel 的視覺特徵。

Model 在訓練中學到一件事：條件訊號在空間上有結構性變化 → 時間上應該產生 shot 變化。Storyboard 和 mood board 走同一條編碼路徑，差別在於 storyboard 的 feature map 自帶空間差異，mood board 沒有。

## 模型實際看到的是什麼

整張圖，沒有 panel 分割。Vision encoder 的 feature map 中，左上方 token 對應 panel 1 的構圖，右上方對應 panel 2，依此類推。grid 的排列規律被 encoder 理解為空間結構——和它理解「照片裡有兩個人」是同一種能力。

Panel 上的文字標註（"CU"、"push-in"、"0-3s"）**會被讀取**——oimi.ai 的案例中，storyboard 上的運鏡註釋確實影響了輸出。但讀取的機制未知：可能是 vision encoder 內建的識字能力，也可能是 ByteDance 的 Seed-VL 家族做前處理。無論哪種，文字同時留在 visual feature 中沒有被移除——這是文字滲入 bug 的根源（OpenArt Handbook：需手動加 "no text overlay on screen"）。

## 鏡頭序列是怎麼生成的

Vision encoder 負責「這張圖長怎樣」——空間結構、panel 內容、文字。但它不負責「panel 1 和 panel 2 之間是什麼關係」。這個關係來自 prompt。OpenArt Handbook 明確要求使用者 "describe the narrative logic between panels in your prompt"——model 不會自己推斷為什麼 wide shot 後面接 close-up。

Prompt 中的敘事描述引導 cross-attention 在不同時間段關注 feature map 的不同空間區域：[Q4：Temporal Attention](../q04-spatial-temporal/) 在時間軸上平滑這些 attention focus 之間的過渡，[Q14：預訓練視覺先驗](../q14-camera-motion/) 補出具體的運鏡方式。

這個機制的副產品是：panel 越多，每格在 feature map 中佔的空間越小，attention 越難區分不同 panel。這就是為什麼社群共識是 **≤4 格（2×2）效果最好**。

:::tip[🎬 導演要點]
- **≤4 panel 最穩**——格數越多 attention 越稀釋
- **角色參考圖和 storyboard 分開上傳**——同一角色在不同 panel 畫得稍有不同，model 可能當成不同的人
- **文字標註寫在 prompt 裡，不要寫在 storyboard 上**
- 完整實戰流程見 [Q17：Storyboard 實戰](../q17-storyboard-practice/)
:::
