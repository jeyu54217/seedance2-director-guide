## 一句話

你上傳的是一張圖，但 Seedance 看到的是一個 shot 序列。storyboard 圖片先經過 **Seed-VL 視覺語言模型**（VLM）處理——VLM 理解 grid 佈局中的 panel 結構、OCR 讀取每個 panel 上的文字標註，然後視覺特徵按空間位置對應到生成序列的不同時間段。

## 核心問題：一張圖怎麼被當成多個 shot？

九宮格 storyboard 是一張 JPEG，不是九張獨立的圖。如果模型只是把整張圖當成一個全局視覺條件（和 mood board 一樣），它不可能區分 panel 1 的 wide shot 和 panel 2 的 close-up。但 Seedance 顯然能做到——輸出的 shot 順序和 storyboard panel 順序對應。

答案藏在 Seedance 的 vision encoder 裡。

## Seedance 論文引用了什麼

Seedance 2.0 論文 Introduction 第一段列出其技術棧時，明確寫道：

> "Seed-VL multimodal vision-language models [3, 4, 9] for cross-modal semantic understanding"

引用 [9] 是 **Seed1.5-VL**（[arxiv:2505.07062](https://arxiv.org/abs/2505.07062)）——ByteDance 自研的視覺語言模型，532M vision encoder + 20B 參數的 MoE LLM。它在 60 個公開 benchmark 中 38 個達到 SOTA，具備 agent-centric 任務能力（GUI 控制、遊戲操作）。

DataCamp 技術分析描述 Seedance 2.0 的多模態 encoder：「不是一個大漏斗，而是一組各自預訓練的 encoder——每個模態有自己的 encoder。」

架構簡圖：

```
Text   → Text Encoder ──┐
Image  → Vision Encoder ─┤    Shared Latent
Audio  → Audio Encoder ──┼→   Space  →  DiT  →  Decoder  →  影片+音頻
Video  → Video Encoder ──┘         ↑
                          Cross-Attention 查閱所有模態條件
```

Storyboard 圖片走的是 Image → Vision Encoder 這條路。關鍵是：這個 encoder 不是簡單的 CLIP image encoder，而是一個 VLM，具備理解圖像結構和讀取文字的能力。

## 從圖片到 shot 序列：五個推論步驟

**Step 1：Vision Encoder 編碼整張圖**

Storyboard 作為單張圖上傳。ComfyUI workflow 中使用 `ByteDance2ReferenceNode` 直接吃 contact sheet，沒有預先切片步驟。Vision encoder 輸出一個保留了空間結構的 feature map——每個 spatial position 對應原圖的某個位置（左上角、右下角等）。

**Step 2：VLM 隱式理解 grid 結構**

VLM 在預訓練階段看過大量漫畫、multi-panel 佈局、分鏡圖。不需要一個獨立的 "panel detection 模組"——理解「這是一張被切成 3×3 的九宮格」和它理解「這張照片裡有兩個人」是同一種能力：emergent visual understanding。panel 之間的邊框線、空白間距、排列規律，就是 VLM 用來識別 grid 結構的視覺線索。

**Step 3：OCR 讀取 panel 上的文字標註**

Modern VLM 內建 OCR。Storyboard 上的 "CU"、"push-in"、"0-3s" 等標註不是被當成 visual texture 保留，而是被 VLM 讀取為語義文字。這說明了為什麼官方 prompt 範例寫 "draw on the storyboard, shot scale, camera movement, visuals and copy"——"copy" 就是 VLM 從 panel 上讀取的文字。這些文字被轉成 text tokens，和 prompt 文字一起進入 cross-attention 條件。

**Step 4：空間位置對應時間軸**

這是整個機制最關鍵的一步。Seedance 1.0 的 **Multishot MM-RoPE** 為不同來源的 token 提供獨立的位置編碼。學術界的 Kaleido（[arxiv:2510.18573](https://arxiv.org/abs/2510.18573)）提出 R-RoPE——為 reference image tokens 分配獨立的 rotary position encoding，讓模型能區分「這個 token 來自 reference 1 的 spatial position (x₁,y₁)」和「這個 token 來自 reference 2 的 spatial position (x₂,y₂)」。

應用到 storyboard：panel 1（左上）的 visual token 帶著空間位置 (x₁, y₁)，panel 2（中上）帶著 (x₂, y₁)，依此類推。在 DiT 的 joint attention 中，這些空間座標被 learned mapping 對應到生成序列的不同時間區段——model 從訓練中學到「左上方的 visual condition → shot 1 → 時間段 1」。這不是 hard-coded 規則，是從大量 multi-shot 訓練資料中湧現的映射。

**Step 5：Cross-Attention 在不同時段查閱不同空間區域**

生成 shot 1 的時間段，cross-attention 的 query 傾向 attend 到 panel 1 對應的空間區域（因為訓練時學到 spatial↔temporal 對應）。進入 shot 2 時，attention 轉移到 panel 2 的區域。Temporal Attention（[Q4：時空注意力分工](../q04-spatial-temporal/)）在時間軸上平滑兩個 attention focus 之間的過渡——視覺上表現為運鏡。

VINO（[arxiv:2601.02358](https://arxiv.org/abs/2601.02358)）的架構和這個推論一致：VLM 輸出 interleaved conditioning tokens，multimodal DiT 透過 cross-attention 查閱這些 token。EasyRef（[arxiv:2412.09618](https://arxiv.org/abs/2412.09618)）證明 multi-reference 之間需要 attention-based interaction（而非簡單的平均），間接支持「不同 spatial region 被不同時間段 attend」的機制。

:::tip[🎬 導演要點]
- Storyboard 上的**文字標註真的會被讀取**——"CU"、"push-in"、"0-3s" 寫清楚，不要只畫圖
- Panel 排列順序要和時間軸對應：左上→右上→左下→右下是標準閱讀順序，model 也會這樣理解。不要跳躍排列
- 實戰技巧見 [Q17：Storyboard 實戰](../q17-storyboard-practice/)——面板數量、文字滲入防範、與角色圖的分工
:::

:::caution[⚠️ 誠實揭露]
Seedance 1.0/2.0 論文均未描述 storyboard 圖片的內部解析機制。以下為推論：(1) Vision encoder 使用 Seed-VL——論文有引用但未確認即為 storyboard 前處理組件；(2) OCR 讀取文字標註——基於 VLM 標準能力和官方 prompt 範例推論；(3) 空間位置對應時間軸——基於 MM-RoPE 設計和 Kaleido R-RoPE 類推。VINO 和 EasyRef 為學術界佐證，不等於 Seedance 內部實作。
:::
